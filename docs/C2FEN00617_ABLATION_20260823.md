## Attribution

1. **Resident parametric contingency model: partial improvement.** It reduced scenario 005 Code 2 by 8.736 seconds (4.77%) versus the saved baseline, but the 22-worker scenario 017 run timed out. The reuse mechanism is useful, but not sufficient under heavy concurrency.
2. **Ipopt acceptable-level termination: no standalone improvement.** It did not activate in the standalone 005 ablation (all solves returned full success), 005 slowed, and 017 still timed out. It is not credited with the final speedup. All final 8-worker solves also reached full Ipopt success.
3. **Deterministic longest-first scheduling: meaningful load-balancing improvement.** Against the preceding 22-worker configuration, it reduced 005 by 23.621 seconds and changed 017 from a 102/103 timeout into a complete certified run. It removed the hard-contingency tail, though 22-worker contention still prevented a baseline speedup.
4. **Calibrated concurrency: largest improvement.** Reducing from 22 to 8 workers cut Code 2 from 181.274 to 130.224 seconds on 005 and from 199.621 to 125.348 seconds on 017. This eliminated the MUMPS/CPU-memory contention that made simultaneous first solves take much longer.

Correctness fixes discovered while implementing resident reuse—recursive invalidation of Gravity's parameter-expression caches, canonical PWL state serialization, and explicit exact generator ramp-bound rows—were necessary for equivalence and independent validation, but are not counted as speed improvements.
