# Cold 19,402-bus top-five improvement campaign

## Contract

The objective is to reach at least the fifth-highest feasible competitor raw
objective in GO2 Final Event Division 1 for **all five** C2FEN19402 scenarios.
Targets exclude the ARPA-e benchmark and are recorded without display rounding
in `config/c2fen19402_top5_cached_v1.json`. Published scores are comparison
targets, not global optimality certificates.

Every qualifying run starts from its own unchanged source input, without any
saved solution or other scenario's solution as initialization. Within-run
factorization and verified-state reuse are permitted. Scheduling profiles
contain only task ordering/budgets, not solution vectors. Preserve complete
source contingency coverage, source constraints, the independent `1e-5`
residual gate, official infeasibility zero, and the existing 300-second
normalized-input-to-verification boundary. A partial or timed-out result does
not qualify, regardless of its provisional objective.

The latest passing baseline is algorithm `a1bebd5`, evidence commit `f926188`.
It remains on `codex/all-network-pass-20260915`. Development is isolated on
`codex/c2fen19402-top5-cold-20260915`. The older economic branch and unrelated
untracked reports are preserved.

feasible predictor outputs, without the old negative-two-million threshold.
Disable both optional per-contingency economic LP stages for this mode. Each
of at most four cached corrections/backtracking rounds can replace its
incumbent only after exact nonlinear validation and a strict objective gain.
No source slack cap, tolerance, commitment, ramp bound, or topology rule changes.
The baseline mode remains unchanged and the new mode is explicitly opt-in.

First cold scenario: 095. Keep its 10-second sparse base cleanup and 40-second
sparse AC economic stage unchanged to isolate the corrective change. Component
tests must pass and the implementation/configuration must be committed before
launch. No repeated timing samples of the same revision/configuration.

one improving run alone is not completion.

## V1 cold result and routing defect

Algorithm `125be97`, scenario 095, stopped at the reserved work deadline after
295.309182600 seconds. It completed 1,716/6,579 contingencies and has no complete
official objective or security certificate. No other scenario was launched.
The source model and all RAW/JSON/CON hashes match the frozen baseline.
The base passed (50.663920457 algorithm seconds); its native objective was
200613.950095, close to the prior native 200614.776785.

The post-stop audit found a routing defect in the new opt-in mode: the existing
economic mode bypasses the first-choice rolling corrective seed, but that
condition tested the old CLI flag rather than the effective solver option.
Consequently the new cached mode still inherited costly controls from unrelated
outages within the same run. Cached correction improved each such incumbent
locally but could still be much worse than rebuilding from the common base.
This was not cross-run initialization, but it defeated the economic policy.

The worker logs contain 1,721 successful terminal records, including five
late-finishing records that the controller did not count as in-deadline.
Among those records: 1,368 cached-polish results averaged 3.6603 solver seconds;
351 rolling-seed direct screens averaged 1.3853 seconds. These are concurrent
per-task wall times, not additive end-to-end times. On the 1,721 matching labels,
native objective change averaged -1501455.63 versus the baseline; this biased
partial-label diagnostic is not a full official scenario score.

V2 corrects the guard to use `fast_options.economic_balance_polish`, covering
both economic modes. Both now start each fresh outage calculation from the
common base produced during that same cold run; rolling seeds remain only a
feasibility fallback after fresh prediction fails. All other V1 settings remain
unchanged except the cached correction cap is reduced from four to one after
the measured V1 cost. The task summaries now retain bounded cleanup attribution
(attempts, backtracking, objective and P/Q slack before/after) instead of losing
those fields when transient vectors are deleted. Future qualification still
requires the complete independently verified official result within the
registered deadline.

V2 pre-run validation passed all 63 Python component tests and all four native
CTest groups after rebuilding the Release binary. The registered JSON stays
unchanged; the implementation revision identifies the routing fix and the
one-correction cap. The published comparison workbook SHA256 is
`56146934c9c90e5eff6477246243caa52d1483df4da24b8a5dc0dc0509ee63f0`.

After verifying the terminal Windows/WSL process state, run containment, absence
of reparse points, and the archived status SHA256, the V1 failed run's 3,395
solution-text entries (including hard links) were permanently pruned. Physical
C: space recovered: 3,057,893,376 bytes. The base JSON, logs, original status,
manifest, results and hash-verified compact archive remain. The deleted partial
solution vectors cannot be independently re-evaluated now. No baseline, source
input, code or environment was deleted.
